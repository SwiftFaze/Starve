How to host your own Starve: it runs as one Docker container or one jar, keeps everything in one SQLite file, and is reached in a browser. Setting it up takes about five minutes.

Install

One command, straight from the repository

You need Docker. This builds the image from the master branch (the stable release) and starts it, with nothing to clone:

docker build -t starve https://github.com/SwiftFaze/Starve.git#master && docker run -d --name starve --restart unless-stopped -p 8080:8080 -v starve-data:/data starve

The database lives in the starve-data volume, so it survives updates.

Open http://<your-server>:8080 and go on to first run. The setup code is in docker logs starve.

With Docker Compose

Better if you want to change settings in a file. You need Docker with the Compose plugin:

git clone https://github.com/SwiftFaze/Starve.git
cd Starve
docker compose up -d

Compose builds the image, keeps the database in a named volume (starve-data, mounted at /data), restarts Starve with the machine and checks its health at /actuator/health. Starve listens on port 8080: open http://<your-server>:8080.

From source

You need JDK 21 or later. Run it straight from the checkout:

./mvnw spring-boot:run

Or build a jar once and run that:

./mvnw -B package -DskipTests
java -jar target/starve-*.jar

Run this way, the database is ./data/starve.db next to where you started it.

First run: the admin account

A fresh Starve has no accounts, so every page sends you to /setup. It asks for a one-time setup code, which Starve prints to its log when it starts:

Starve setup code: XATS-W5KJ

From source, it is in the terminal where you ran ./mvnw spring-boot:run. With the one-command install:

docker logs starve 2>&1 | grep "setup code"

With Docker Compose:

docker compose logs starve | grep "setup code"
  1. Enter the code. It lives in memory only; each restart prints a new one until an account exists.
  2. Choose an admin username: 3 to 32 letters, digits, dots, underscores or hyphens.
  3. Choose a password of at least 10 characters. There is no email reset, so keep it safe.

You are signed in and land on the timeline. From then on /setup is closed and the code stops working. Everything after that happens inside Starve itself.

On your phone

Starve can live on your home screen like an app: it opens on the timeline, full screen, without the browser's address bar, in the colours of your theme.

  • iPhone and iPad: open Starve in Safari, tap Share, then Add to Home Screen.
  • Android: open Starve in Chrome, open the menu, then Install app (or Add to Home screen).
  • Desktop Chrome or Edge: click the install icon at the end of the address bar.

It is the same Starve you use in the browser: you stay signed in, the player keeps playing, and links out to a post's site open in your browser. Nothing is kept offline.

Your data

Everything lives in one SQLite file: /data/starve.db in Docker, or ./data/starve.db from source. Point it elsewhere with STARVE_DB_PATH or --starve.db.path. To back up, stop Starve and copy that file.

Items are kept 90 days. Favourites and items saved for Later are kept until you clear them.

What Starve records

  • No analytics, no tracking and no ads. Every script and font is served by Starve itself.
  • No activity log. The server log holds the first-run setup code and nothing about what anyone reads or watches.
  • What you read, star and save is stored in the database, because the feed needs it, and never leaves your server.
  • The server only reaches out to fetch your sources: their feeds, article pages, icons and SoundCloud track details.
  • In the browser, thumbnails and post images load straight from the sites that publish them, and playing a video or track loads YouTube's privacy-enhanced player (youtube-nocookie.com) or SoundCloud's widget, so that service sees the play.

Configuration

Set these as environment variables (in docker-compose.yml under environment) or as -- arguments:

VariableDefaultWhat it sets
STARVE_DB_PATH./data/starve.dbWhere the database file lives
STARVE_POLL_INTERVALPT30MHow often every source is fetched
STARVE_RETENTION_MAX_AGEP90DHow long items are kept
SERVER_PORT8080The port Starve listens on

Durations use the ISO 8601 form: PT15M is 15 minutes, P30D is 30 days.

Update

One-command install: build again from master and replace the container. The volume keeps your data.

docker build -t starve https://github.com/SwiftFaze/Starve.git#master && docker rm -f starve && docker run -d --name starve --restart unless-stopped -p 8080:8080 -v starve-data:/data starve

Docker Compose:

git pull
docker compose up -d --build

The database is upgraded in place when Starve starts. From source, pull and run it again.
